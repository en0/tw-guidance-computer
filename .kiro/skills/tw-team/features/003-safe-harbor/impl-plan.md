# Implementation Plan: Safe Harbor

## Overview

Add a RED ALERT overlay to the HUD when turns drop below a configurable threshold, showing the fastest BFS route to the nearest safe sector (Federation space or StarDock). Add a `tw safe-harbor` CLI command for on-demand route checking. Adjust turn warning color thresholds and make all thresholds configurable via `config.ini`.

## Architecture Decisions

### Config Value Reading

Turn thresholds are application configuration stored in the same INI file as profiles. The `ProfileStore` Protocol is about profile management — adding generic config reading breaks its cohesion.

**Approach**: Add a concrete `get_config_value(profile_name: str, key: str, default: str) -> str` method on `IniProfileStore` (NOT on the `ProfileStore` Protocol). The composition root already constructs `IniProfileStore` directly in `resolve_db_path()` — this follows the same pattern. A new `resolve_config()` function in `compose.py` constructs `IniProfileStore` once and extracts both the db path and turn thresholds, eliminating the double-construction problem.

### Safe Sector Query

The `GameStateStore` gets a new method `get_safe_sector_ids() -> list[int]` that returns sector IDs where `region == 'The Federation'` OR the sector has a port with `port_class == 0`. Single SQL query. The use case receives a flat list of target sector IDs and runs BFS.

### HUD Caching

The HUD caches the `SafeHarborRoute` result and only re-calls the use case when the player's sector changes. This matches the existing `_art_cache` / `_art_sector` pattern. Fields: `_safe_harbor_cache: SafeHarborRoute | None` and `_safe_harbor_sector: int | None`.

### Overlay Content Generation

Overlay text content is generated by a pure helper function (`format_alert_overlay`) that takes the route result and turns remaining, returning a list of strings. This is testable without curses. The TUI adapter calls this helper and renders the strings with curses attributes.

## Work Units

### Unit 1: Domain — SafeHarborRoute and TurnThresholds Value Objects

- **Layer**: domain
- **Files**: `src/tw_guidance_computer/domain/models/safe_harbor.py`, update `domain/models/__init__.py`
- **Description**: Two frozen dataclasses in one file:
  - `SafeHarborRoute`: fields `destination_sector: int`, `destination_name: str`, `route: list[int]` (required, no default). Derived property `hops -> int` = `len(route) - 1`. Validates `destination_sector >= 1`, `route` non-empty.
  - `TurnThresholds`: fields `yellow: int = 200`, `red: int = 100`, `alert: int = 50`. Validates all positive, `yellow > red > alert`.
  Both types re-exported from `domain/models/__init__.py` and added to `__all__`.
- **Dependencies**: None.
- **Tests**: `tests/test_domain/test_safe_harbor.py` — construction, frozen, validation failures, `hops` property, `TurnThresholds` defaults, custom values, invalid ordering rejected.

### Unit 2: Port — Safe Sector Query on GameStateStore

- **Layer**: application/ports
- **Files**: `src/tw_guidance_computer/application/ports/game_state_store.py`
- **Description**: Add `get_safe_sector_ids() -> list[int]` to `GameStateStore` Protocol. Returns sector IDs that are Federation space OR contain a Class 0 port.
- **Dependencies**: None (Protocol definition only).
- **Tests**: Tested via adapter implementation (Unit 3).

### Unit 3: Adapter — SQLite Safe Sector Query

- **Layer**: adapters
- **Files**: `src/tw_guidance_computer/adapters/outbound/sqlite_store.py`
- **Description**: Implement `get_safe_sector_ids()` on `SqliteGameStateStore`. SQL:
  ```sql
  SELECT DISTINCT s.id FROM sectors s
  WHERE s.region = 'The Federation'
  UNION
  SELECT DISTINCT p.sector_id FROM ports p
  WHERE p.port_class = 0
  ```
- **Dependencies**: Unit 2 (port definition).
- **Tests**: `tests/test_adapters/test_sqlite_store.py` — returns Federation sectors, returns StarDock sectors, returns union without duplicates, returns empty list when no safe sectors.

### Unit 4: Adapter — IniProfileStore Config Value Method

- **Layer**: adapters
- **Files**: `src/tw_guidance_computer/adapters/outbound/ini_profile_store.py`
- **Description**: Add a concrete method (NOT on the Protocol) `get_config_value(profile_name: str, key: str, default: str) -> str` on `IniProfileStore`. Reads from `[profile:{name}]` section with `configparser`'s built-in `[DEFAULT]` fallback. If key not found in section or defaults, returns the provided `default` argument. Update `_DEFAULT_CONFIG` to include threshold keys in `[DEFAULT]`:
  ```ini
  [DEFAULT]
  default_profile = default
  turn_warning_yellow = 200
  turn_warning_red = 100
  turn_alert_threshold = 50
  ```
- **Dependencies**: None.
- **Tests**: `tests/test_adapters/test_ini_profile_store.py` — reads key from profile section, falls back to `[DEFAULT]`, falls back to provided default when key absent entirely.

### Unit 5: Application — FindSafeHarbor Use Case

- **Layer**: application
- **Files**: `src/tw_guidance_computer/application/find_safe_harbor.py`
- **Description**: `@final` class `FindSafeHarbor` with `execute(from_sector: int) -> SafeHarborRoute | None`.
  - Calls `self._store.get_safe_sector_ids()` to get target set
  - If `from_sector` is in the target set, returns a `SafeHarborRoute` with `route=[from_sector]` and appropriate label (calls `get_sector` for region name, `get_port` to check if StarDock)
  - Otherwise, runs BFS from `from_sector` using `get_all_warps()` (undirected, same as `FindPath`), terminating at the first safe sector reached
  - Returns `None` if no path exists
  - To determine `destination_name`: calls `self._store.get_sector(destination)` for region, and `self._store.get_port(destination)` to check if it's StarDock
  Constructor: `__init__(self, store: GameStateStore) -> None`
- **Dependencies**: Unit 1 (SafeHarborRoute), Unit 2 (port method).
- **Tests**: `tests/test_application/test_find_safe_harbor.py` — finds nearest Federation sector, finds StarDock, returns None when isolated, returns self-route when already safe, prefers closer safe sector.

### Unit 6: Application — Overlay Content Helper

- **Layer**: application (or adapters/inbound as a helper module — lives alongside tui.py)
- **Files**: `src/tw_guidance_computer/adapters/inbound/alert_overlay.py`
- **Description**: Pure function `format_alert_overlay(route: SafeHarborRoute | None, turns_remaining: int, current_sector: int) -> list[str]` that produces the overlay text lines (without curses formatting). Handles three cases:
  - Route found: "TURNS CRITICAL: N remaining", "Nearest safe harbor: Sector X", "Route: A → B → C", "Distance: N hops". Route truncated to first 8 sectors + "... (N more)" if > 10 hops.
  - Already safe (route with `hops == 0`): "TURNS CRITICAL: N remaining", "You are currently in a safe sector.", "(destination_name)"
  - No route (None): "TURNS CRITICAL: N remaining", "Uhoh, I think you're in trouble.", "No known route to safe space."
  Returns a list of content lines (border rendering is the TUI's job).
- **Dependencies**: Unit 1 (SafeHarborRoute type).
- **Tests**: `tests/test_adapters/test_alert_overlay.py` — all three cases, route truncation, correct formatting.

### Unit 7: Adapter — HUD Overlay Rendering + Turn Warning Colors

- **Layer**: adapters
- **Files**: `src/tw_guidance_computer/adapters/inbound/tui.py`
- **Description**:
  Changes to `__init__`:
  - Accept `turn_thresholds: TurnThresholds` parameter
  - Add `_safe_harbor_cache: SafeHarborRoute | None = None`
  - Add `_safe_harbor_sector: int | None = None`

  Changes to `_render`:

  - If yes, check if sector changed: `if self._safe_harbor_sector != status.sector_id` → call `self._uc.find_safe_harbor.execute(status.sector_id)`, update `_safe_harbor_cache` and `_safe_harbor_sector`

  - Render overlay: centered box using `╔═╗║╚═╝` border in red bold, content lines inside
  - If turns >= threshold, clear cache: `self._safe_harbor_cache = None`, `self._safe_harbor_sector = None`

  Changes to `_render_header`:
  - Update turn warning color logic using thresholds:
    ```python
    if turns < self._thresholds.alert:    # < 50: red bold
        attr = RED | BOLD
    elif turns < self._thresholds.red:    # < 100: red bold
        attr = RED | BOLD
    elif turns < self._thresholds.yellow: # < 200: yellow bold + reverse
        attr = YELLOW | BOLD | REVERSE
    else:
        attr = YELLOW | BOLD
    ```

  - Replace `resolve_db_path()` with `resolve_config()` in `compose.py`:
    ```python
    def resolve_config(
        profile_name: str | None, config_path: Path | None = None
    ) -> tuple[Path, TurnThresholds]:
        """Resolve db path and turn thresholds from config.

        Constructs IniProfileStore once, extracts both values.
        """
        from tw_guidance_computer.adapters.outbound.ini_profile_store import IniProfileStore

        store = IniProfileStore(config_path or default_config_path())
        store.ensure_config_exists()
        effective_name = profile_name or store.list_profiles().default_name
        profile = store.get_profile(effective_name)
        db_path = Path(profile.db_path)

        yellow = int(store.get_config_value(effective_name, "turn_warning_yellow", "200"))
        red = int(store.get_config_value(effective_name, "turn_warning_red", "100"))
        alert = int(store.get_config_value(effective_name, "turn_alert_threshold", "50"))
        thresholds = TurnThresholds(yellow=yellow, red=red, alert=alert)

        return db_path, thresholds
    ```
    Keep `resolve_db_path()` as a thin wrapper calling `resolve_config()` for backward compatibility (CLI doesn't need thresholds).

  - `cli.py`: register `safe-harbor` subcommand, dispatch to `cli.safe_harbor()`
- **Dependencies**: All previous units.
- **Tests**: `tests/integration/test_safe_harbor_wiring.py` — verify `resolve_config` reads from config, falls back to defaults, constructs valid `TurnThresholds`.

## Risk Notes

1. **BFS performance**: With sector-change caching, BFS runs at most once per sector transition while the alert is active. For typical game sizes (1000 sectors, ~3000 warps), BFS completes in <1ms. No performance concern.

2. **Overlay vs. art panel interaction**: The overlay renders LAST in `_render`, overwriting whatever is beneath (including the art panel). This is intentional — the alert is more important than the art.

3. **Config key naming**: Using `turn_warning_yellow`, `turn_warning_red`, `turn_alert_threshold` as INI keys. The `configparser` DEFAULT cascade means setting them once in `[DEFAULT]` applies to all profiles unless overridden.

4. **Threshold validation ordering**: `TurnThresholds` enforces `yellow > red > alert`. If a user sets invalid values in config.ini, the `ValidationError` propagates to the entry point. Handled by the existing `GuidanceError` catch in `hud.py`/`cli.py`.

5. **FindSafeHarbor in UseCases container**: Adding it as a required field means existing tests that construct `UseCases` need updating. Builders should update `conftest.py` fixtures.

6. **`resolve_db_path` backward compatibility**: The CLI uses `resolve_db_path()` and doesn't need thresholds. Keep it as a thin wrapper: `return resolve_config(profile_name, config_path)[0]`. No breaking changes to CLI entry point.
